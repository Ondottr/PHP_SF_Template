# QWEN.md — Project Context

## Project Overview

**PHP Simple Framework — Template** (`nations-original/php-simple-framework-template`) is the official
project template for the [PHP Simple Framework (PHP_SF)](https://github.com/Ondottr/PHP_SF_Platform).
It bootstraps a full working application in one command and demonstrates the framework's **dual-kernel
architecture**: the PHP_SF kernel and a native Symfony 7.4 kernel coexist in the same application
(`App/Kernel.php` extends the Symfony Kernel; PHP_SF bootstraps around it).

- **Language/Runtime:** PHP **8.3** (pinned: `"php": "8.3.*"`), `declare(strict_types=1)` in every PHP file
- **Backend framework:** Symfony `^7.4` components + `nations-original/php-simple-framework` `^3.1`
- **Persistence:** Doctrine ORM with **multiple named entity managers** (PostgreSQL / MySQL / MariaDB), Redis cache
- **Frontend:** Webpack 5, Babel, Sass, Bootstrap 5, jQuery 4, axios; Prettier for formatting
- **Testing:** Codeception 5 (Unit / Functional / Acceptance), PHPUnit 12, Foundry fixtures, Jest for JS
- **Messaging:** Symfony Messenger + RabbitMQ (AMQP)
- **License:** ISC. Docs: [wiki.nations-original.com/framework](https://wiki.nations-original.com/framework)

## Directory Layout

```
App/                    # Application code (PSR-4: App\)
├── Http/Controller/    # PHP_SF attribute-routed controllers
├── Http/SymfonyControllers/  # Native Symfony controllers (fallback path)
├── Http/Middleware/    # Custom middleware
├── Entity/<EmName>/    # Doctrine entities, one dir per entity manager (created by init.sh)
├── Repository/<EmName>/# Repositories, same per-EM layout
├── DataFixtures/       # Doctrine fixtures (per connection)
├── Enums/ Command/ EventSubscriber/ Maker/ Story/ Abstraction/
├── Doctrine/           # App-level Doctrine extensions (e.g. UnqualifiedTableQuoteStrategy)
└── Kernel.php          # App kernel (extends Symfony Kernel)
Platform/               # Local checkout of PHP_SF_Platform sources (git-ignored; scanned by PHPStan)
config/                 # Symfony bundle config; constants.php is generated, NOT committed
templates/              # PHP view classes (PSR-4: App\View\ => templates/)
templates_twig/         # Twig templates
functions/              # Global helper functions (composer "files" autoload)
src/                    # Frontend JS sources; Jest unit tests live in src/Tests/Unit
tests/                  # Codeception: Unit/ Functional/ Acceptance/ Support/ (Support is generated)
docker/                 # CI Dockerfile + DB init scripts
staging/                # Staging deploy helpers
public/                 # Web root
```

Autoloaded via composer `files`: `config/constants.php`, `functions/functions.php`, `functions/view_functions.php`.

## Building & Running

| Task | Command |
|---|---|
| First-ever project init (interactive: DB connections, `.env`, `constants.php`, User entity, assets) | `./init.sh` |
| Install an already-configured project on a new machine | `./install.sh` |
| Start dev server (port 7000 default; uses Symfony CLI with HTTPS if available) | `./run.sh [port]` |
| Symfony console | `bin/console` |
| Composer deps | `composer install --ignore-platform-reqs --no-scripts` |
| Frontend dev build (watch) | `npm run dev` |
| Frontend production build | `npm run build` |
| Infrastructure services (Postgres 7003, MySQL 7005, MariaDB 7006, Redis 7002, Memcached 7001, RabbitMQ 7004, Selenium 4444) | `docker-compose up -d` |

### Per-connection Doctrine commands

The template ships a `dummy` default entity manager that **fails fast on purpose** (prevents accidental
cross-DB access). Real connections are added by `init.sh`; always address them explicitly:

```bash
bin/console doctrine:database:create --if-not-exists --em=<name>
bin/console doctrine:schema:create --em=<name>
bin/console doctrine:fixtures:load --no-interaction --em=<name>
bin/console <name>:make:entity        # per-EM entity maker generated by init.sh
```

Environment variables per connection follow `DATABASE_<EM_NAME_UPPER>_{HOST,PORT,USER,PASSWORD,DBNAME,VERSION}`
in `.env` (from `.env.example`). Test DB name: `DATABASE_<EM>_DBNAME_TEST` or `<DBNAME>_test` fallback.

## Testing & Static Analysis

```bash
vendor/bin/codecept run                     # All Codeception suites (Unit, Functional, Acceptance)
vendor/bin/codecept run Functional          # Single suite
vendor/bin/codecept build                   # Regenerate actor classes (tests/Support) after suite config changes
composer stan                               # PHPStan level 6 (phpstan.neon, baseline: phpstan-baseline.neon)
composer cs-check                           # php-cs-fixer dry-run with diff
composer cs-fix                             # php-cs-fixer apply
npm run test:unit                           # Jest — JS unit tests in src/Tests/Unit
```

- PHPStan config: level 6 over `App/` and `tests`, `scanDirectories: Platform/src/`, Symfony container XML
  from `var/cache/dev/`, Doctrine object manager loader (`phpstan-doctrine-loader.php`),
  baseline in `phpstan-baseline.neon`. Regenerate baseline only as a last resort.
- Codeception coverage is enabled (thresholds 30/60) over `App/`, `Platform/`, `templates/`, `functions/`.
- Acceptance tests use the Selenium container (host network mode, Firefox reaches the app on port 7000).

## Development Conventions

### PHP

- **`declare(strict_types=1)` on the same line style** enforced by a custom fixer
  (`App/declare_strict_types_one_line` in `.php-cs-fixer.dist.php`).
- Code style: `@PSR2` + `@Symfony` plus project rules — spaces inside parentheses `( $arg )`,
  alphabetical imports, short array/list syntax, single quotes, trailing commas in multiline,
  ordered class elements (traits → constants → properties → constructor → public/private methods),
  two-blank-line section separators in classes (custom `App/class_section_separation` fixer).
- **`App/Entity/` is excluded from php-cs-fixer** — entities use an intentionally compact
  getter/setter style. Do not "fix" entity formatting.
- Risky fixers are allowed and expected: `strict_comparison`, `strict_param`, `void_return`.
- No `@author` tags or license headers in individual files.
- EditorConfig: UTF-8, LF, 4-space indent for PHP, 2-space for JS/JSON/YAML, max line 120.

### Multi-database architecture

- Each DB connection = one entity manager with its own `App/Entity/<Name>/` and `App/Repository/<Name>/`
  namespaces, wired in `config/packages/doctrine.yaml`. Never reference one EM's entities from another.
- MySQL/MariaDB EMs use `App\Doctrine\UnqualifiedTableQuoteStrategy` (schema in `ORM\Table` is treated as a
  DB prefix; prevents spurious CREATE/DROP from `doctrine:schema:update`).
- A `User` entity implementing `PHP_SF\System\Interface\UserInterface` is **required** (authentication,
  sessions, access control). `init.sh` creates it and wires `setApplicationUserClassName(...)` into
  `bin/console`, `public/index.php`, and `tests/bootstrap.php` — keep those three entry points in sync
  if the User entity changes.

### Frontend

- Sources in `src/`, built by Webpack to `public/`. Production builds obfuscate JS (`webpack-obfuscator`)
  and purge unused CSS; dev builds disable cache (`npm run dev`).
- Prettier (`.prettierrc.json`) for JS/JSON/etc.

### Contributing / Git

- Commits **must be DCO-signed**: `git commit -s` (`Signed-off-by:` trailer required, unsigned PRs rejected).
- Branch from `master`; open issues for bugs/features before large PRs; security reports go via
  SECURITY.md, never public issues.
- `roave/security-advisories` is a dev dependency — dependency updates that introduce advisories will fail.

### Environment files

- `.env` is generated from `.env.example` by `init.sh`/`install.sh` and never committed as-is;
  `.env.dev` / `.env.test` hold environment overrides. `config/constants.php` is generated from
  `config/constants.example.php` (git-ignored) — edit the example file, not generated constants.

## CI / Docker

- `.github/workflows/build-image.yml` rebuilds the CI image (`ghcr.io/ondottr/php-sf-ci`) from
  `docker/Dockerfile` on change; staging deploy/cleanup workflows handle preview environments;
  `template-cleanup.yml` runs when the template is instantiated.
- Dependabot is enabled (`.github/dependabot.yml`); CODEOWNERS governs review routing.

### Framework development workflow (Platform/)

`Platform/` is a git-ignored local checkout of **PHP_SF_Platform (the framework itself)**, which PHPStan
scans via `scanDirectories`. When making changes to framework code (`PHP_SF\*` symbols):

1. Wire `Platform/` into this project as a **symlinked Composer path repository** — add to `composer.json`:

   ```json
   "repositories": [
       { "type": "path", "url": "Platform", "options": { "symlink": true } }
   ]
   ```

   then `composer update nations-original/php-simple-framework` so
   `vendor/nations-original/php-simple-framework` becomes a symlink to `Platform/`.
2. Test framework changes live in this project before anything is pushed.
3. **Never** edit the `vendor/` copy directly, and **never** push untested framework changes to git.

If PHPStan reports missing `PHP_SF\*` symbols, the `Platform/` checkout is absent or stale.

## Gotchas
- `tests/Support/` is generated Codeception scaffolding — run `vendor/bin/codecept build`, never edit by hand.
- `config/packages/doctrine.yaml` is maintained by `init.sh`'s YAML round-trip (header comments preserved);
  manual edits must keep the `dummy` connection and `when@test` DBNAME overrides intact.
- Composer install uses `--ignore-platform-reqs --no-scripts` in setup scripts because the app requires
  many PHP extensions (apcu, amqp, redis, memcached, gd, intl, yaml, …) that may not all be present locally.
